# Enterprise Service Incident Report

Document ID: INC-2026-00417
Classification: Internal
Status: Resolved
Incident Date: 2026-08-14
Severity: SEV-2
Affected Service: Enterprise Order Processing API

## Executive Summary

On 2026-08-14, the Enterprise Order Processing API experienced elevated latency and intermittent request failures. The incident affected order submission and status-update operations for selected customers in the APAC region.

The incident lasted approximately 47 minutes. No permanent data loss was identified.

## Impact

Affected customers: 126
Failed API requests: 18,742
Estimated delayed orders: 3,184
Service availability during incident: 98.6%

Customer-facing symptoms included HTTP 429 and HTTP 503 responses, delayed order confirmations, and increased API response times.

## Timeline

09:42 UTC - Monitoring detected elevated API latency.
09:46 UTC - On-call engineer acknowledged the alert.
09:51 UTC - Error rate exceeded SEV-2 threshold.
10:03 UTC - Root cause isolated to database connection pool exhaustion.
10:14 UTC - Connection pool limits increased and unhealthy connections recycled.
10:21 UTC - Error rates returned to normal levels.
10:29 UTC - Incident declared resolved.

## Root Cause

A configuration change increased the number of concurrent application workers without a corresponding increase in the database connection pool. Under peak traffic, available connections were exhausted, causing requests to queue and eventually fail.

## Corrective Actions

1. Add automated validation between worker and database connection limits.
2. Increase monitoring coverage for connection pool utilization.
3. Add load-test scenarios for APAC peak traffic.
4. Update deployment checklist with capacity validation.
5. Review similar configuration across production services.

## Data Integrity

Post-incident reconciliation completed successfully. No evidence of permanent customer data loss or unauthorized data access was found.
